# Architecture

## T03 storage root and session repository

`LocalLectureSTT`는 macOS 15 이상, arm64 전용 SwiftUI 앱 target 하나와 두 test target으로 시작한다.

```text
LocalLectureSTT (app)
├── App             composition root와 scene 진입점
├── Features        화면과 사용자 상호작용 단위
├── Application     use case와 orchestration의 예정 경계
├── Domain          프레임워크 비의존 타입과 규칙의 예정 경계
└── Infrastructure  외부 시스템 구현의 예정 경계

LocalLectureSTTTests             unit smoke test
LocalLectureSTTIntegrationTests  app module을 연결하는 integration smoke test
```

현재 경계는 하나의 app target 안에 있는 **논리적 경계**이며 compile-time module 분리는 아직 없다. `Domain`은 Foundation과 Swift 값 타입만 사용하며, 저장소·오디오·STT 구현에는 의존하지 않는다.

목표 의존 방향은 다음과 같다.

```text
App → Features → Application → Domain
App → Infrastructure → Application/Domain
Domain → 다른 앱 계층에 의존하지 않음
```

MVP는 단일 프로세스다. 이후 비동기 구성 요소는 XPC나 별도 프로세스로 이동할 수 있도록 경계를 유지하되, T02에서는 그 추상화나 XPC를 만들지 않는다. AppKit, IOKit, AVFoundation은 필요한 adapter 또는 Infrastructure에만 제한할 예정이다.

### Domain contracts

`SessionID`, `TranscriptSegmentID`, `SessionEventID`, engine/model ID와 언어 코드는 서로 대입할 수 없는 작은 값 타입이다. `EngineIdentity`와 `ModelIdentity`는 세션 재현에 필요한 version, revision, checksum을 함께 보존한다.

`AbsoluteTime`은 wall-clock `Date`를 밀리초 정밀도로 고정하고 시간대 포함 ISO 8601 문자열로 JSON에 기록한다. `MediaMilliseconds`, segment sequence와 segment count는 별도 음수 불가 정수 타입이므로 wall-clock 시간·초 단위 부동소수·미디어 위치가 섞이지 않는다.

모든 독립 저장 DTO(`SessionMetadataDocument`, `TranscriptDocument`, `TranscriptJournalRecord`, `SessionEventRecord`, `FinalizationCheckpointDocument`)는 정수 `schemaVersion`을 가진다. 중앙 `SchemaVersionPolicy`는 현재 v1만 허용하고 미래 버전을 조용히 현재 버전으로 해석하지 않는다. `TranscriptJournalRecord`는 `recovery/transcript.journal.jsonl`의 독립적인 한 레코드이며, T03의 `JSONLWriter`가 이를 append-only로 기록한다.

`SessionLifecycle`은 현재 처리 상태와 녹음 결말인 `CaptureOutcome`을 분리한다. 정상 종료는 `recording/paused → securing → finalizing → completed`이며 securing부터 outcome이 `completed`다. 중단 복구는 `interrupted → securing/finalizing → interrupted`이고 outcome은 계속 `interrupted`여서 파일 복구 완료가 정상 녹음 완료로 바뀌지 않는다. 같은 상태 적용은 검증된 lifecycle의 no-op이고, 다른 모든 허용되지 않은 전이는 domain error다. 앱 시작 시 잔존한 `recording`/`paused` + `inProgress` 변환은 T09가 담당한다.

`FinalizationCheckpointDocument`는 명세의 여덟 단계가 앞 단계부터 순서대로 완료됐음을 보존한다. 마지막으로 완료된 단계의 재적용만 idempotent하며, 이미 완료한 더 이른 단계를 다시 적용하면 regression, 다음 단계를 건너뛰면 skipped error다. 비연속 저장 상태도 거부한다. 실제 JSONL append는 T03, 오디오 마무리와 checkpoint 실행은 T08/T09 범위다.

### Storage roots

`StorageRootID`는 UUID 기반의 안정적인 앱 고유 식별자다. `Infrastructure/StorageRootManager` actor는 Application Support의 `LocalLectureSTT/Storage/storage-roots.json`에 schema v1 registry를 atomic JSON으로 저장한다. Registry는 active root와 historical root의 app-scoped bookmark, 표시용 이름·경로와 관리 시각을 보존한다. 표시 경로는 UI 안내용일 뿐 접근 권한으로 사용하지 않는다.

`StorageRootCatalog`는 bookmark/URL을 노출하지 않고 active root ID와 `StorageRootReference(summary, isActive)` 목록만 Application에 제공한다. 따라서 T04는 catalog의 stable root ID를 사용해 Infrastructure의 lexical scoped-access 경계에서 각 historical root를 처리할 수 있다. Historical root 재승인은 해당 ID와 현재 active root를 유지하며, active root 변경은 명시적 directory selection만 수행한다.

`FoundationSecurityScopedBookmarkCodec`은 `.withSecurityScope` bookmark를 만들고 resolve한다. 매 repository operation은 manager의 lexical `withAccess` 내부에서 resolved URL을 사용한다. 성공한 start는 operation의 성공·실패 모두에서 한 번 stop된다. resolve/start 실패는 UI에 `reauthorizationRequired`로 전달되며 stale bookmark는 같은 root ID의 bookmark를 atomic하게 교체하고 갱신된 summary를 반환한다.

`Features/StorageRootViewModel`은 AppKit `NSOpenPanel` adapter를 분리해 명시적인 선택·변경·재승인 버튼만 제공한다. 앱 시작 시 active root 복원을 시도하지만 panel을 자동으로 열지 않는다. 테스트용 view construction은 in-memory preview controller를 사용하므로 Application Support나 panel을 건드리지 않는다.

### Session files

`FileSessionRepository` actor는 active 또는 historical root의 scoped operation에서만 session files를 읽고 쓴다. `SessionFolderName`은 주입된 time zone으로 `YYYYMMDD-HHMMSS_<8-char-lowercase-id>`를 만들며 제목과 무관하다. 새 session은 폴더와 `recovery/`만 만들고, 기존 이름은 collision으로 거부하며 자동 정리하지 않는다.

`SessionArtifact`만이 파일 경로를 만들며 canonical/recovery source와 derived artifact를 명시적으로 분류한다.

```text
metadata.json                         authoritative/recovery
audio.m4a                             authoritative/recovery
transcript.json                       authoritative/recovery
events.jsonl                          authoritative/recovery
recovery/audio.recovery.mov           authoritative/recovery
recovery/transcript.journal.jsonl     authoritative/recovery
recovery/finalization.checkpoint.json authoritative/recovery
transcript.txt, transcript.md         derived
```

`AtomicFileWriter`는 same-directory exclusive temp file → write → `synchronize()` → close → POSIX atomic rename → directory sync 순서로 JSON을 교체한다. rename 전 실패는 기존 destination을 건드리지 않으며 writer가 소유한 temp만 best-effort로 제거한다. `JSONLWriter`는 repository actor의 직렬화 안에서 완전히 encoded 된 단일 JSON line과 LF를 append하고 flush한다. append 실패 뒤의 possible partial trailing record를 복구하는 일은 T20/T26 범위다.

### T04 rebuildable session catalog

`Application/SessionCatalog.swift` keeps SQLite and URL out of the application boundary with `SessionCatalogItem`, `CatalogProjection`, `CatalogPresence`, scan reports, and scanner/store protocols. Files always win: `present` displays metadata status, `missing` displays `.missing`, and `unreadable` displays `.error` without discarding the last valid metadata status.

The pre-existing T03 `StorageRootControlling` selection/reauthorization methods are an intentional exception: they accept `Foundation.URL` for the Feature-to-Infrastructure selection boundary. T04 does not expand that exception. Domain and every new catalog projection/scanner/store/report contract remain URL-free; scanner URLs exist only within Infrastructure's lexical security scope.

`SessionFileScanner` reads active and historical roots inside read-only security scopes, enumerates direct children only, and rejects symlinks, bad folder names, invalid metadata, unsupported schemas, and ID mismatches. Only complete root scans mark unseen rows missing; partial or unavailable roots preserve existing rows.

`SQLiteSessionCatalogStore` is an actor over system SQLite3 at `Application Support/LocalLectureSTT/Catalog/session-catalog.sqlite3`. Schema v1 stores IDs, immutable folder, projection fields, presence, and millisecond timestamps. It uses parameter binding, WAL, FULL synchronous, foreign keys, trusted_schema off, finite busy timeout, and one `BEGIN IMMEDIATE` batch transaction. Existing DBs receive read-only user-version/quick-check validation first; future schemas remain untouched, while corrupt catalogs are retained under `Catalog/Corrupt/<timestamp>-<uuid>/` before rebuild.

`CatalogStartupCoordinator` is composed once in the app and coalesces startup/root-change reconciliation. T04 deliberately does not add the T21 list UI.

### T09 startup recovery

`SessionRecoveryCoordinator` is the app-lifetime owner for startup and root-change recovery. It uses `SessionFileScanner`'s root/bookmark-scoped recovery discovery rather than SQLite rows, reports small URL-free candidates and preserved typed issues, then submits recoverable sessions to the same `AudioFinalizationCoordinator` used by T07. `recording` and `paused` metadata are changed to `interrupted` only by a pinned, compare-before-write repository operation; a failed write never reaches the audio queue. `preparing/notStarted` is conservatively changed once to `error/notStarted` with diagnostic code `preparationAbandoned`.

Completed metadata with a `metadataCompleted` checkpoint takes a distinct, read-only `verifyExistingCanonical` request on that same serial queue. Request kind is part of the coordinator cache identity, so an older resumable-finalization result cannot stand in for a new terminal inspection. Each new discovery pass requests a fresh terminal verification while joining an in-flight identical verification; a settled success never certifies subsequently replaced bytes. `FinalizationRun` records source observation at open as absent or present with a fingerprint, then activates that observation for the terminal run through every post-await validation and the validation after the `beforeRelease` barrier. A present source must retain its fingerprint for provenance; only a durable `recoveryDataRemoved` checkpoint may transition a present source to an absence that then remains absent. An initially absent prefix-8 source must also remain absent through read-lease release; any appearance or replacement is terminal inconsistency. Prefixes 6/7 preserve source absence as `missingRecoverySource`, never an invented canonical-only success. The verifier uses T08's pinned media inspection and, while recovery source exists, source/canonical provenance comparison; it obtains a read lease and cannot export, publish, issue a proof, remove recovery audio, or write metadata/checkpoint/catalog/events.

`SessionActivityRegistry` is the common ownership boundary. T07 reserves the selected root before it creates a folder, promotes that reservation to the exact session once the location is known, and keeps it through T08 worker settlement. T09 atomically claims a candidate before every metadata/finalization action; it therefore reports a live current-process item rather than racing it after a snapshot read. Root selection and reauthorization request `recovery.refresh()` through `CatalogStartupCoordinator`; a refresh arriving during a pass is retained. Explicit cancellation invalidates its generation, cancels only finalization jobs it claimed, and waits for their settlement before another pass can begin. Normal and cancellation settlement use the same result mapper: a delivered T08 success remains success, the first actual failure remains first, and subsequent diagnostic/cleanup warnings remain warnings. Diagnostic events use a conservative JSONL validator, so malformed/incomplete event bytes are retained rather than appended after.

Recovery only awaits discovery before a new recording starts. Existing media work remains asynchronous, keeps T08's no-clobber/pinned-file validation, and never removes recovery audio. T09 leaves transcript/canonical/derived work and checkpoint steps 4–8 to later tasks. It re-reconciles the rebuildable catalog after file work; a catalog failure is reported separately and does not roll back audio recovery. Recovery UI renders root reauthorization failures as independent root notices/actions, so a historical-root error cannot overwrite same-root session success, first failure, warnings, or the active recording UI.

### T05 microphone capture and input signal monitor

`MicrophonePermissionAuthorizing` separates side-effect-free authorization-status lookup from an explicit permission request. `MicrophoneCaptureController` is the single actor owner of capture lifecycle. T07 composes it once and keeps permission request and capture start behind the explicit recording Start action; app/view construction only performs a status lookup.

`AVAudioEngineMicrophoneDriver` owns the AVAudioEngine input tap, Core Audio default-input/alive listeners, and configuration notification registration. It snapshots the current default input before start. A changed default identity or lost active input sends one terminal typed event and never continues the generation on a replacement device. The callback bridge copies the tap's planar Float32 buffers into a frame-major, interleaved, application-owned `PCMChunk`; AVFoundation buffers and Core Audio IDs never cross into Application.

Each generation exposes independent bounded streams: recording uses `bufferingOldest` and treats every overflow or terminated enqueue as terminal `recordingBackpressure`; realtime speech uses `bufferingNewest`, reports a cumulative discontinuity count, and cannot block or terminate recording. The callback does only format validation, Float32 copy, bounded enqueue, and level aggregation; it does no I/O, inference, UI work, or actor await. A terminal overflow/event creates one asynchronous lifecycle cleanup action, not one task per frame.

`InputSignalMonitor` supplies a throttled stream of normalized peak, RMS dBFS, peak dBFS, state, sequence, and monotonic time. It is independent of VAD. A scheduler checks for no frames as well as silent frames; after 5 seconds without signal at or above -60 dBFS it emits one `noInput` state without stopping capture. Signal at or above -55 dBFS clears it. T07 consumes the authoritative recording PCM plus device/level/capture state; T18/T19 consume the best-effort speech stream and perform their own 16 kHz conversion/VAD.

STT, journal compact, derived file rendering, app-start session recovery와 전체 세션 목록/완성형 녹음 UI는 후속 Task 범위다. T08의 오디오 단계는 아래 별도 경계로 구현한다.

### T06 recoverable fragmented audio writer

`AudioRecorder` is an Application-only contract with framework-free Sendable lifecycle, summary, error, and event values. `AVFoundationAudioRecorder` is its Infrastructure actor implementation. Infrastructure-only output-lease, converter, and writer-backend seams are the same boundaries used by production and deterministic fault tests; AVFoundation and URL values never cross into Application. The recorder fixes a `SessionLocation` and capture generation, verifies the pre-created non-symlink session/recovery layout and destination, rejects an existing `recovery/audio.recovery.mov`, and never deletes a partial output.

`StorageRootManager.acquireWriteLease` holds scoped root access from writer configuration through asynchronous `finishWriting`; `StorageRootWriteLease.release()` is idempotent. The writer emits an audio-only `.mov` with AAC-LC mono 48 kHz, 96 kbps target settings, a 1-second initial fragment interval and 10-second following interval. A persistent converter explicitly averages every input channel before stateful 48 kHz resampling, and cumulative converted frames define a continuous zero-based output timeline.

An operation gate serializes start/append/flush/stop across actor suspension points. Every recording has an ownership token that is revalidated after framework awaits, so readiness/finish callbacks and cleanup from an older operation cannot mutate a newer writer, lease, state, or summary. All converter, readiness, append, flush, finish, storage, and cancellation errors enter one terminal transition: the first typed error is retained, state remains `stopping` until detached best-effort writer finish and lease release complete, then becomes `failed`. Input finish, writer finish request, scope release, and terminal event are each guarded exactly once. The event stream exists at recorder construction, so a failure remains observable to a subscriber that attaches after the failure. T07 combines the capture stream, recorder events, and session journal; T08 finalizes the retained recovery MOV as an audio-only stage; T09 will discover/recover incomplete sessions.

### T07 recording session coordinator and minimal UI

`RecordingSessionCoordinator` is an Application actor and the sole owner of one recording attempt. Its framework-independent boundary contains configuration, observable snapshot/result/failure values, a microphone-capture seam, recorder factory, root check, catalog refresh, clock, and ticker. An attempt token plus one start operation and one settlement operation isolate actor reentrancy: every suspension that can change resource ownership is followed by token/lifecycle validation, old observers cannot mutate a later session, and no second session opens until the current capture/writer settlement is complete.

The explicit Start transaction is root availability → permission status/request → session folder → `.preparing/.notStarted` metadata → capture start → recorder start → recording PCM pump and observers → `.recording/.inProgress` metadata → `recordingStarted`. The fixed `SessionLocation` returned at folder creation is retained for the whole attempt, so an active-root change cannot redirect files. Capture can buffer primary PCM before writer start; the pump consumes `recordingPCM` in sequence and does not depend on a speech/STT consumer.

Normal Stop first marks the stream completion as expected, disables actions, and closes capture intake. It then waits for the primary pump to drain every already accepted chunk before recorder flush/stop. Only a validated T06 summary may provide written frames and final media duration. The coordinator then appends one `recordingEnded`, writes `.securing/.completed`, and reconciles the rebuildable catalog. T07 intentionally retains `recovery/audio.recovery.mov`; it creates no `audio.m4a`, transcript, derived text, or finalization checkpoint. T08 owns `.securing → .finalizing` and final audio publication. It deliberately leaves metadata `.finalizing` with the original capture outcome. The later whole-session pipeline must actually produce and verify transcript/derived files and terminal metadata/catalog before using T08's separate recovery-audio cleanup API.

Capture, pump, recorder, storage, cancellation, and user-stop signals converge on the same settlement operation. The first typed failure is retained; cleanup errors cannot replace it. Recorder terminal events become one stable session event, a shared ended-event key prevents duplicate journal lines, recoverable bytes/session folders are never deleted, and a started session becomes `.interrupted/.interrupted` rather than false `.securing` success. Catalog reconciliation failure is only an observable warning after file-authoritative persistence.

`RecordingSessionViewModel` maps the actor snapshot onto a minimal SwiftUI flow. With an available root, idle shows title, language, permission status, and Start; recording shows start time, elapsed monotonic time, device, throttled level/no-input state, and Stop; settlement disables duplicate actions; success explicitly says recovery audio is safely stored and finalization is pending. UI observation/action tasks do not own or cancel capture, the PCM pump, writer, or settlement.


### T08 final audio and application lifetime

`Application/AudioFinalization.swift` contains Codable/Sendable requests, progress/snapshots, stable error codes, media/file verification reports, and the completion-proof/verifier contracts. Requests freeze `SessionLocation`; neither an active-root lookup nor URL/framework objects cross the new Application boundary. `AudioFinalizationPolicy` fixes duration comparison tolerance at 150 ms. `AudioDescription.bitRate` is the 96 kbps target; measured compressed average bitrate is separate in `AudioMediaReport`.

`AudioFinalizationCoordinator` owns one serial pending queue and a single flight per root/session/request-kind. It retains small requests/proofs/latest results and bounded observer streams, not media buffers or progress history. `resume` and `verifyExistingCanonical` are deliberately separate cache keys, while the one queue and location-wide cancellation retain the existing active-work and cleanup protections. Detached workers keep synchronous hashing/media loops away from capture and the coordinator actor. Explicit cancellation arbitrates a first cause through `AudioFinalizationControl` and waits until writer/reader cleanup and scope release. Cancelling a caller or observation task does not cancel this work. Generation checks reject late progress callbacks. A new attempt cannot start while the previous flight is releasing resources.

`RecordingFinalizationCoordinator` is composed once in the app. It forwards T07 recording operations and submits only `.secured` results to the finalization queue before returning essential Stop. It never waits for export/validation. The standalone T07 coordinator still creates recovery-only artifacts. Active recording snapshots and background audio snapshots remain separate in the view model; the UI uses actual stages and explicitly says that remaining finalization is pending after audio readiness.

`FinalizationFileAccess` pins root/session/recovery directory descriptors, rejects symlinks (including broken ones), non-regular files and hard-linked artifacts, validates document/session identities, and rechecks inode/device/size/nanosecond timestamps across awaits. Content evidence uses streaming SHA-256 with 64 KiB scratch space. JSON replacement stays relative to pinned descriptors. Canonical publication uses macOS `renameatx_np(RENAME_EXCL)` plus directory sync; existing `audio.m4a` is never replaced or moved. An unusable staging file can be moved exclusively to a UUID retained path, which is returned diagnostically and never automatically cleaned.

`FinalizationMediaFiles` carries the pinned directory owner, the previously verified source evidence and an open read-only source descriptor into the remux backend. After `startWriting` creates staging, it also owns an open descriptor for that output inode. The backend rechecks directory/source identity and output absence or inode ownership after each track/duration/format load, writer-readiness suspension and finish callback, and directly before writer creation/start, sample read/append and finish. Replacement aborts before the next media operation, rather than being discovered only after remux returns. All of these types and URLs stay in Infrastructure.

`AVFoundationFinalizationMedia` validates the AAC decoder configuration (object type 2, 48 kHz, mono), streams compressed sample payloads in order, checks timeline continuity and reader terminal status/error, and remuxes via `AVAssetWriter(.m4a)` with `outputSettings: nil` and a source format hint. Reader trim attachments preserve AAC priming/remainder semantics. Separate fresh PCM readers seek the beginning and final 250 ms. Payload-free reader boundary markers are not audio and are skipped; real sample counts/bytes and terminal reader completion remain required. Compressed payload provenance ignores container bytes and compares packet sizes/order/content. Each media buffer is capped at 1 MiB; PCM endpoint windows and hash scratch memory remain bounded. A single failure path fixes the first cause before cleanup, stops an active reader once and finishes an already-started writer before releasing the media owner and security scope. It does not call `cancelWriting`, whose documented file deletion could target a replacement pathname. Best-effort finish closes the existing writer while retaining partial output; finish/cleanup failures are secondary warnings. A writer that has not started is released without a pathname-based deletion. The real-file tests cover directory replacement before/after start and replacement of the open staging file itself.

`FileAudioFinalizer` records `workingAudioSecured` only after source validation, writes preserving `.finalizing` metadata, creates/closes/syncs staging, records `finalM4ACreated`, validates and exclusively publishes, reopens/verifies canonical, then records `finalM4AVerified`. Projection and best-effort catalog refresh follow. Required write errors fail the result; diagnostic and catalog errors are separate warnings. Earlier completed checkpoint steps are skipped, and later pipelines' metadata/checkpoint bytes are preserved. With recovery still present, terminal metadata matching its capture outcome plus a checkpoint through `catalogUpdated` returns `audioRevalidated` after media verification. Metadata/checkpoint bytes and recovery remain unchanged. An audio-only prefix or a still-pending catalog step continues to return `audioReadyAwaitingRemainingFinalization`; the coordinator and view model preserve that distinction. After recovery removal, an explicit request can carry the sealed whole-completion proof to revalidate canonical audio without changing terminal metadata or checkpoint bytes. Existing canonical adoption rechecks file/directory sync before checkpoint advancement. Publication is never undone after a later error. Results expose verified evidence separately from observed `presentPaths`.

Recovery deletion is a separate operation. `CompletionEvidenceAuthority` lazily stores a private 32-byte signing key in Application Support on explicit proof issuance; construction has no I/O. A new authority instance can validate persisted proof after restart. Missing, corrupt, symlinked, or permissively accessible key files fail closed without rotation. It issues sealed evidence only after current file hashes/identities, full terminal metadata, checkpoint through `catalogUpdated`, source/final provenance, and a trusted `RemainingFinalizationVerifying` implementation agree. That future pipeline verifier is responsible for transcript semantics, deterministic derived files, and committed catalog acknowledgment. T08 does not supply a production transcript verifier or fabricate empty output. Cleanup revalidates all bound files after awaits and directly before unlink, deletes only `recovery/audio.recovery.mov`, syncs its directory, then records `recoveryDataRemoved`. A failed final checkpoint can be retried with the same full proof even when source is already absent. Cancellation before unlink preserves source; after the deletion commit point it cannot falsify the removal result. Checkpoint transitions can append diagnostics, but checkpoint/journal crash-atomic exactly-once is not claimed.

See [T08 acceptance](T08_ACCEPTANCE.md) and [T09 acceptance](T09_ACCEPTANCE.md) for assertion-level evidence and fault windows.

### T10 app lifetime and lifecycle policy

`LocalLectureSTTApp` shares one `LifecycleWorkAuthority` with T07, its recording/finalization wrapper, T08, T09 and `MacLifecycleDelegate`. This in-memory, synchronously locked admission authority acquires a lease before preparation/discovery/enqueue can begin. New operations advance an admission generation; an already-owned normal Stop handoff retains its generation and overlaps leases. The first lease acquires one injected ProcessInfo token and the last releases it. Idle-system sleep, automatic and sudden termination are disabled; display sleep is allowed. Delayed stream observations cannot release a newer operation's token. The activity reason contains no user data. App construction configures these owners without starting observation or work; SQLite catalog construction is deferred until an explicit catalog operation. The existing T03 path-resolution boundary is unchanged.

`AppLifecycleCoordinator` owns policy and app-lifetime observation; T07/T08/T09 still own data and resources. Streams trigger fresh owner reads. A synchronous readiness result is usable only while its admission generation still matches and there are no owned leases. AppKit callbacks never await actors or disk I/O. Unknown/busy readiness returns terminate-later. Repeated quit requests share one owned task/presenter and one reply. The admission captured before presentation survives essential save and cleanup; a delayed choice cannot interrupt a newer recording. At the actual MainActor reply gateway the authority rechecks under the admission lock with no intervening await. Teardown cancels one pending reply, while the still-owned task prevents an early retry. No path waits for full export.

T07 reports `EssentialTerminationSaveResult` only after its required terminal metadata/events, accepted PCM drain, writer flush/stop, observers and resource settlement. Intentional sleep/quit is a reason, distinct from the first operational failure. Required write/flush/stop failures deny termination and retain prior bytes; later failures remain warnings and catalog refresh stays best effort. A deliberately closed input stream during a held start-event write is an expected terminal, not a second capture failure. No T11 transcript/checkpoint placeholders are written. T08 owns its existing durable audio checkpoint prefix. Cancellation with cleanup/media-cleanup warnings requires attention, while catalog/diagnostic warnings alone do not.

Sleep and direct power-off own a cleanup generation. The recording wrapper owns requests waiting for initial T09 discovery: it retains their admission epoch and first interruption reason. Lifecycle invalidates an already-admitted pending start before T09 cancellation can release its discovery waiter, then joins that rejection during settlement. The start lease overlaps the T07 handoff; a pre-sleep request cannot turn into new capture when discovery is cancelled. Explicit quit uses the same boundary. A normal Stop already in securing, including its wrapper's pending T08 enqueue, is joined rather than rewritten to interrupted. Cleanup quiesces T09 (suppressing a deferred refresh restart), then the shared T08 queue, then wrapper registry-release tasks. Subsequent sleep generations join preceding cleanup. Wake acknowledges and waits for its generation, rejects stale generations across the wake-event await, and calls the existing T09 refresh. Recording never restarts automatically. Leases span cleanup and handoff, and settled owners publish after resource release so a no-window auto-exit can be reconsidered.

Window state is transient in memory. Main and Settings count as titled visible NSWindows; hidden windows and NSPanel subclasses do not. ### T11 engine contracts and deterministic fake

`Domain/STTContracts.swift` adds Foundation-only Codable/Sendable/Equatable capabilities, model/options, session configuration, owned audio, request context, hypothesis snapshots and stable typed errors. Existing capture `PCMChunk` remains unchanged and does not cross this serializable boundary.

`Application/STTEngine.swift` defines the Sendable orchestration protocol: load, start, infer, end, cancel, unload, and immutable capabilities. `any STTEngine`, its request feed and stream are control-plane handles, not payload DTOs. Load accepts only a descriptor; installed-model lookup and filesystem verification belong to T12/adapters. No fake is constructed by app or preview composition.

Audio is an owned Float32 frame-major array with validated rate, channel count, sample count, finite samples and safe arithmetic. The default fake advertises mono 16 kHz interleaved input. The value representation can describe other finite formats, but the engine explicitly rejects formats outside its advertised capabilities. Inputs are at most 30 seconds (checked before rounding), 960,000 samples, and at least one rounded millisecond. Duration is nearest integral millisecond, ties away from zero. Request start plus duration is overflow checked. Hypothesis segments use **session-relative media milliseconds**, within request bounds and in non-overlapping ascending order. Adapters must add the request's nonzero media offset to native offsets. These hypotheses are full replacement snapshots, and a final is final only for that request; T18 reconciliation and T20 canonical persistence are absent.

Accepted inference returns one single-consumer `STTEventFeed`. Admission/control errors throw `STTEngineError`; accepted requests emit partial values followed by exactly one final/failed/cancelled value and finish. There is no second throwing terminal channel. Revisions must increase by one. A bounded newest-two stream coalesces unconsumed partials and always retains terminal evidence for a late first subscriber. Payload text/segment limits bound each retained event. A second subscription fails explicitly. Cancellation while awaiting stream events and explicit `withdraw()` cancel only that request. Breaking iteration alone does not cancel engine-owned work: callers should explicitly withdraw if they intend cancellation. A bounded latest-value observation supports deterministic assertions without keeping history.

`Infrastructure/FakeSTTEngine.swift` is an actor with one serial logical FIFO worker. Construction starts no tasks, clock, I/O or inference. The injected value scenario has bounded preparation/request scripts and cleanup delay; `advance(by:)` is the explicit logical clock acknowledgment, with all due work completed before return. Equal deadlines use script array order, then FIFO order. Request delays begin when processing starts, never when queued. There is no real-time scheduler. A small configurable capacity (1–16, default 2) counts **pending requests only**, excluding one active request. A full backlog rejects only the incoming request and consumes neither its sequence nor a script. Queued cancellation frees capacity immediately; active cancellation waits for its configured owned cleanup, then the next accepted request can start.

All admissions append to the FIFO; only the driver promotes its head and sets the processing origin. An accepted external `deliver` callback synchronously drives pending promotion, due events and control settlement before returning, including an early final/failed callback while `end` waits. The driver uses the same private ownership-checked publication path without recursively calling `deliver`, so it never resumes processing with a stale local worker after recursively activating another request. Rejected callbacks do not drive or mutate state.

| Control | Transition and settlement |
| --- | --- |
| load | unloaded/ready → loading → ready; failure/caller cancellation → unloaded; active session/preparation/cleanup rejects mutation |
| start | ready with matching model → starting → running; failed/cancelled start → ready; duplicate/concurrent start rejects |
| infer | running only; exact pinned session and increasing sequence; pre-admission validation cannot mutate work |
| end | running → draining → ready; rejects new work, gracefully processes the accepted FIFO; concurrent end joins |
| cancel | running/draining → cancelling → ready; queued work terminates immediately, active work joins cleanup; concurrent cancel joins |
| unload | active work/preparation → unloading → unloaded after cleanup; concurrent unload joins; unloaded unload is explicitly idempotent |
| settled end/cancel | no session → invalidLifecycle, rather than pretending another session ended |

Control caller cancellation never abandons end/cancel/unload cleanup. Load/start caller cancellation selects typed cancellation and retains any already-selected operational cause. Terminal request cancellation is explicitly idempotent. Every publication checks the internal generation, full request context, and revision, including the stale-adapter callback fault seam.
